# Jarvis Core Vision

Jarvis exists to convert a collection of infrastructure services, scripts, repositories, sensors, databases, media workflows, and AI models into one governed operational system.

A model is only one component.

Jarvis should be able to:

- collect state from the environment;
- normalize raw data into predictable structures;
- build evidence instead of dumping raw logs into models;
- retrieve relevant design intent and prior knowledge;
- route work to the correct domain and capability;
- use specialist agents for focused analysis;
- combine specialist findings through a Chief;
- validate proposals with deterministic tools;
- write results into safe review locations;
- escalate difficult work only when justified;
- require human approval before production-changing actions.

The architecture is intentionally local-first. Local AI handles routine monitoring, Home Assistant reviews, YAML and script drafting, infrastructure audits, media-state reasoning, event classification, memory retrieval, and recurring household operations. Cloud AI is reserved for exceptional reasoning, major redesigns, unusual failures, or other work that exceeds local capability.

Jarvis should become more useful than a generic cloud chatbot inside this environment because it combines:

```text
MODELS
  +
MEMORY
  +
TOOLS
  +
LIVE ENVIRONMENT
  +
DOMAIN KNOWLEDGE
  +
POLICIES
  +
HUMAN GOVERNANCE
```

Raw frontier intelligence is only one part of the system.
