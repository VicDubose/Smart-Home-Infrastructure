# Evidence Register and Acceptance

**Maps to parent README:** Sections 2, 18, 19, and 21
**Evidence cut-off:** Specialist handoffs through October 30, 2026. This is not a live SKYNET query.

## Purpose

This folder distinguishes what has been implemented, what has passed a scoped test, what has been staged, and what still requires operational acceptance.

## Status vocabulary

- **Accepted within scope:** the stated component passed its stated acceptance criteria.
- **Prepared / staged:** artifacts exist, but live deployment or operation is not proven.
- **Shadow / review-only:** private candidate evidence; not production publication.
- **Deferred:** intentionally not required for the current closeout.
- **Open / not verified:** required evidence has not been supplied.

## Rule

Never promote a component to production-ready because a README exists, a package was uploaded, a service is running, or a local test passed. Production acceptance requires source freshness, scope, reconciliation, policy, failure recovery, and a dated receipt.
